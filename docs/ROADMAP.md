# خطة تحويل ASUS ZenPad C 7.0 إلى جهاز سيارة خفيف

الجهاز المستهدف: ASUS ZenPad C 7.0 Z170CG / P01Y / WW، بمعالج Intel SoFIA 3GR وذاكرة RAM سعتها 1GB.
النظام المتحقق منه: Android 5.0.2، API 21، ABI أساسي x86، وتحديث أمني 2017-04-01.

## مبادئ التنفيذ
- نبدأ من النظام الحالي؛ لا حاجة لتنزيل حزمة RAWDATA ذات 2GB للمرحلة الأولى.
- لا تفليش ولا تعديل أقسام النظام في هذه المرحلة.
- لا نحذف أو نعطّل حزم المصنع بالتخمين. نجمع قائمة الحزم وحالة الجهاز أولاً، ثم نصنّف كل حزمة حسب وظيفتها واعتمادياتها.
- نفضّل التعطيل القابل للتراجع على الحذف. تبقى خدمات الإقلاع والواجهة والإعدادات والاتصال والصوت واللمس والبطارية والتخزين والبلوتوث والموقع محمية إلى أن يثبت العكس.
- كل مرحلة لها سجل تغييرات وطريقة رجوع.

## المرحلة 0 — فحص الجهاز الفعلي (بدأت)
1. جمع معلومات البناء والعتاد والتخزين والبطارية.
2. جمع حزم النظام وتطبيقات المستخدم والحزم المعطّلة.
3. أخذ لقطة من العمليات واستهلاك الذاكرة.
4. عدم إجراء أي تعديل على الجهاز أثناء الفحص.

الأداة: tools/windows/collect-device-inventory.ps1، قراءة فقط ولا تنفذ تعطيل/حذف/تثبيت.

## المرحلة 1 — تخفيف البرامج الأساسية
بعد مراجعة تقرير المرحلة 0:
- تصنيف التطبيقات إلى: أساسي ومحمي، اختياري آمن للتعطيل، يحتاج اختبار، ممنوع المساس به.
- إيقاف التطبيقات الترويجية/المكررة/غير المستخدمة فقط إذا تأكدنا من عدم اعتماد خدمات النظام عليها.
- اختبار الإقلاع واللمس والصوت والواي فاي والبلوتوث وGPS والشحن بعد كل مجموعة صغيرة.
- الاحتفاظ بأوامر إعادة التفعيل لكل حزمة.

## المرحلة 2 — واجهة السيارة
- Launcher مستقل وخفيف، متوافق مع Android 5.0.2 وAPI 21 وx86.
- شاشة رئيسية عربية، أزرار كبيرة، تباين واضح، واختصارات للخرائط والموسيقى والهاتف/البلوتوث والإعدادات.
- لا خدمات خلفية مستمرة ولا إعلانات ولا تحليلات ولا مكتبات ثقيلة.
- الواجهة تفتح التطبيقات الموجودة على الجهاز فقط وتتعامل مع غيابها بوضوح.

## المرحلة 3 — الطاقة والشاشة
- استقبال حدث توصيل/فصل الطاقة لاختبار السلوك.
- تشغيل الشاشة عند توصيل الشاحن بعد اختبار صلاحيات Android 5 على الجهاز.
- إطفاء الشاشة عبر Device Admin بعد موافقة المستخدم وتفعيل صلاحية مسؤول الجهاز؛ لا ندّعي أن التطبيق يستطيع ذلك بصمت.
- فحص السلوك بعد إعادة التشغيل وفصل/إعادة توصيل الطاقة.

## المرحلة 4 — التحقق والتحسين
- قياس الذاكرة والعمليات وزمن الإقلاع قبل/بعد.
- اختبار الاستخدام المطوّل والحرارة والشحن والصوت والملاحة.
- لا يُعتمد أي تغيير يسبب فقدان وظيفة أو عدم استقرار.

## المرحلة 5 — قرارات النظام العميقة (لاحقاً)
تعديل system image أو kernel أو ترقية Android 7/8 مشروع منفصل، ويتطلب إثبات توافق boot/recovery وأحجام الأقسام وطريقة الاستعادة. لا نبدأه قبل نجاح المراحل السابقة وتوفر نسخة إنقاذ مناسبة.
